# BiT-128 普通版：OP 哈希、随机源与 NTT

2026-10-30，Apple arm64 / Clang 21。仅普通 128 位版本，未加入预计算或
256 位。哈希/SHAKE 使用 OP；生产随机请求直接使用 `OP_trng`，无软件
DRNG；正 NTT、逆 NTT、点乘全部使用 OP。此前 `macos-arm64[,-o3]` 和
`macos-arm64-trng-o2/o3` JSON 为历史记录，当前数据使用 `op-ntt-o2/o3`。

## NTT 接口与表示

`OP_ntt256_init` 配置 N=256、q=7681、完整 8 层、k=0、count=2。
只读根表含正/逆各 256 项，按原版变换顺序排列，根从 R16 表示转换为
R32=2^32 表示。`inv_q` 位模式为 2340676097，`inv_n=1912` 是
256^-1*R32 mod q；正变换 index=0，逆变换 index=1。

`OP_ntt256/OP_intt256` 的输入输出均在 [0,q)；`OP_cwm` 返回
`a*b*R32^-1 mod q`。点乘累加保持在 [-q,3q)，随后 CPU 乘公开常数
R32 mod q=5569 并做 Barrett 约减，恢复普通域。算法侧没有本地 NTT 回退。
软件 OP 后端用固定层数蝶形和乘移位约减，不按秘密系数分支或索引根表。
正变换中间值 <9q、逆变换和 <256q；乘积上界决定安全使用的 32/64 位路径。

适配层三个 256 项 int32 缓冲共 3072 B，彼此独立。持久多项式仍用 int16，
避免矩阵缓存翻倍。软件后端借用静态只读根表（2048 B ROM），只保留一个
可写指针（本机 8 B），没有复制 8 KB 全局表。

## 内存

KeyGen/Sign/Verify 每次只 malloc 一次，拒绝循环内不再分配。所有退出路径
擦除工作区再释放。内存探针逐字节核对释放块、分配失败、无剩余块。

| 操作 | 堆负载峰值 | 完整预留预算 | PC 分配器取整后的预算 |
|---|---:|---:|---:|
| KeyGen | 14,920 B | 22,784 B | 24,248 B |
| Sign | 27,872 B | 35,736 B | 36,536 B |
| Verify | 18,944 B | 26,808 B | 28,344 B |

预算为：堆 + 3072 B 栈 + 4400 B 公钥/私钥/签名 + 128 B 分配器/段对齐
预留 + 256 B 外部库栈预留 + 8 B OP 状态。算法本身没有可写全局状态。
PC 列使用非 sanitizer 的 `malloc_size` 实测尺寸 16,384/28,672/20,480 B
（含测试头），不是整个进程 RSS。均低于更严格的 40,000 B 门槛。

| 已知 C/软件 OP 调用链上界 | O2 | O3 |
|---|---:|---:|
| KeyGen | 2144 B | 2144 B |
| Sign | 2448 B | 2800 B |
| Verify | 1984 B | 1984 B |
| 可选随机源探测 | 128 B | 128 B |

`.su` 与汇编枚举直接调用及尾调用，尾调用保守当嵌套。保留通用 OP 中
不可达的其他哈希分支，仅排除 BiT 不使用的链模式递归。无 VLA。
这不是单函数栈帧值；已叠加完整已知 C 调用链。外部 libc 未展开，256 B
是工程预留。脚本支持 Clang/GCC AArch64/x86 汇编；板端需复核真实驱动、
分配器、中断、任意长度消息及其他固件占用，PC 预算不代表完整板端固件保证。
板端驱动若额外复制根表、持有 DMA 缓冲，必须另行计入。

矩阵和公钥 NTT 缓存保留。KeyGen 谱检查/NTT、Verify 编解码/NTT、Sign
解码秘密向量/NTT 分别共享阶段 union。Sign 在最后一次 NTT 后恢复秘密向量，
再做挑战乘法；采样阶段与后续工作区也复用。Gaussian 字节批次借用尚未产生
坐标的 Q13 对象表示，维持原 127 候选批次；编码临时区按有效格式有界。
工作区均按 C 类型自然对齐，没有将大暂存移到全局。

## 兼容性与错误路径

生产随机数改变后不要求密钥/签名逐字节相同。比较驱动构建原版 SM3 DRNG、
确定性测试 OP 版、真实 OP 生产版三个独立程序。O2/O3 下均通过：

1. 测试 OP 重放原随机流：32 把密钥、512 份签名字节一致。
2. 生产新版验原版签名、原版验生产新版签名：每方向 512 份。
3. 原版私钥由生产新版签名、生产新版私钥由原版签名：每方向 512 份，
   分别由对方验签通过。
4. 完整 KAT 与原版逐字节一致，SHA-256：
   `fe956ca45525b0aa6e5a656e2c04f786d9ddefc9eedbe66b9c4e0ed323f45751`。

NTT 合同测试在 BiT 软件 OP 和独立的仓库 HQC 通用 OP 后端各跑一次：
48 组原标量正/逆变换对照、R16/R32 原始积换算、往返及朴素
x^256+1 卷积；含零、单位基、全 q-1、随机向量、逆变换最大和边界。
公开常数域转换还穷举 [-q,3q) 累加范围。
固定轨迹中逐次注入 NTT 初始化/正/逆/点乘错误：KeyGen 16、Sign 42、
Verify 23 个位置均失败返回，输出长度归零，工作区释放并擦除。

原 DRNG 和原标量 NTT 仅在 test/reference 作独立对照，不进入生产库。
生产随机失败会清零请求缓冲；`bit_random_init` 只是可选可用性探测。
哈希/随机故障注入、分配失败、完整确定性与真实随机正确性均通过。
ASan/UBSan 全套通过；macOS 缺少完整 LSan，以分配探针补充已执行路径。
CMake/CTest 7/7：两种正确性、内存、哈希 OP、随机 OP、两种 NTT 后端。

## 性能

同一驱动、相同优化等级，预热后串行交替 9 轮；每轮 32 把密钥、512 次
签名/验签。消息长度含 0/1/32/64/135/136/137/512 B。计时包含随机源、
拒绝重试、分配、释放与擦除。下表为各轮均值的中位数，未锁频或绑定 CPU。

原版使用固定 SM3 DRNG 流，适配版使用真实系统 OP 随机源，拒绝次数和
密钥分布不同。这是端到端比较，不能当作相同随机输入下的单独 NTT 成本。

| Sign | 121.326 μs | 116.625 μs | -3.87% |

## 新增算术的汇编检查

用 constant-time-analysis 检查 `core/common/ntt.c` 与 `soft/op_ntt.c`，
覆盖 Apple Clang 21、arm64/x86_64、O2/O3 共 8 组合。结果保存为
`platform/pc/test/results/2026-10-30-op-ntt-ct.json`，对应汇编在
`op-ntt-ct-assembly/`。未发现除法等 error 级指令；原始条件分支 warning
保留，已结合源码/汇编按公开参数校验、地址别名/向量化分支、固定循环、
OP/分配状态返回分组核对。没有系数决定的分支或根表索引。
工具会把局部标签误记为函数名，内部 compiler/optimization 字段未知，
因此外层记录实际编译器和完整命令。此检查只覆盖新增 NTT 算术和上述配置，
不构成完整签名算法恒定时间、算法安全性或硬件时序保证。

独立只读代码复核未发现 Critical/Important 问题。已修正文档性小项：继承的
Barrett 函数仅承诺 |a|<=2^30，覆盖本模块全部调用，避免错误宣称全 int32 域。
