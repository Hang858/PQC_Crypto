# BiT-128 OP Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. User has authorized direct implementation; routine choices require no further confirmation.

**Goal:** Deliver the normal 128-bit BiT module using OP hashes with stack 2–3 KB and RAM below 40,000 B.

**Architecture:** Copy the portable 128-bit reference into the existing include/core/platform layout. Preserve cached matrix and deterministic streams. Use typed heap workspaces with explicit phase unions; share sampler scratch with commitment/response temporaries, not live secrets.

**Tech Stack:** C11, Make, CMake, Clang/GCC, existing software OP hash backend.

**Spec:** `docs/superpowers/specs/2026-10-30-bit128-op-design.md`

## Global Constraints

- Normal 128 only; original releases and other algorithms remain untouched.
- pk/sk/sig = 1264/1696/1440 B. Deterministic KAT bytes unchanged.
- Stack at most 3 KB, aim 2 KB; heap + stack + writable algorithm globals + 4400 B fixed IO + allocation overhead < 40,000 B.
- No large global scratch, no allocation inside coefficient/rejection hot loops; wipe secret heap before release.
- OP failure, allocation failure and invalid inputs return errors; output lengths zero on failure.

## Review Focus

- Split SHAKE reads including zero-length reads preserve byte stream.
- Failed init/absorb/squeeze is sticky and never produces a successful signature.
- Allocation failure at every allocation leaves no live allocations or unwiped secret heap.
- Rejected candidates do not retain overlapping scratch needed for retry.
- Default random initialization uses OP_trng; explicit seed keeps original SM3 DRNG behavior.
